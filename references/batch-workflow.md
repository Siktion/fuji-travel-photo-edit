# 批量照片映射、状态与交付

## 批次开始

1. 盘点输入目录内本轮约定的文件类型与范围。记录总数、文件名、像素尺寸、方向，以及 JPG/RAF 配对关系；无配对的 RAF 单列，不用嵌入预览冒充显影。不要把目录里未纳入本轮的旧文件混进来。
2. 生成稳定的一对一映射：每个源文件对应一个输出行。使用源文件名或稳定编号，不依赖临时排序。大目录先做带编号的联系表/缩略图索引，覆盖约定的候选范围；它只用于粗筛，不能替代逐张全尺寸查看。先做风光、人物、逆光、复杂遮挡等真实存在的代表图；不存在的类别不要补造。
3. 人物批次先判断目标人物是否可可靠定位。单人清晰可识别才按约定编辑；多人、脸部遮挡、远景小脸或目标不明确时保留原片副本并标记 `unchanged` / `uncertain_target`，不得伪称精修。

## 每张的处理状态

清单至少包含：

| 字段 | 内容 |
| --- | --- |
| source | 原片相对路径或安全的源文件标识 |
| output | 实际输出相对路径；未生成时留空并说明 |
| status | `edited`、`unchanged`、`rejected`、`not_generated` 或 `not_processed` |
| method | 实际使用的本地/生成式方法及后端；未调用则写明 |
| source_size / output_size | 实测像素尺寸和方向 |
| review | 实际检查过的整图、面部/细节、对照和发现的问题 |

数量汇总按状态分开列出，且各状态总和应与约定输入数相符。生成候选、被拒绝输出、原样复制和未生成都不能并入 `edited`。清单、调用回执与实际文件互相核对；清单中的 `api_called: true` 等自述不能单独证明真实 API 调用。

## 视觉复核

- 每张对照正确原片查看整图，确认没有场景/人物/建筑/天气漂移，方向和裁切正确。
- 对人物、文字、经幡/宗教纹样、眼镜/发丝、车窗、建筑边缘、擦除区域等放大检查。批次缩略总览不能代替逐张检查。
- 路人默认保留。只有用户明确指定要移除的人物/区域时才处理；遮挡复杂或无法可靠补全时保留痕迹并说明，不生成明显虚假的背景。
- 至少抽查来源与输出数量、文件名一一对应、所有目标文件可解码及实际尺寸。用户要求全量视觉验收时，逐张完成并记录；仅抽样时明确标记为抽样。
- 尺寸或画幅不符、输出重复、映射不确定、场景漂移、人物五官或姿态明显改变时拒绝该候选。不要通过拉伸或补造内容伪造符合比例。
- 哈希可证明某文件是否变化；对照副本与原片哈希一致，通常说明这张没有编辑，必须按实际状态标注。

## 交付

使用新的版本目录；保留旧版本和原片。交付独立图、映射清单、预览或审片页（若有用）及说明。分别写清：输入数、实际编辑数、原样保留数、拒绝/未生成/未处理数、核对范围、输出分辨率限制、RAF 状态和待人工复核项。

ZIP 完整性、图像解码、哈希、尺寸和视觉验收是不同检查。只报告实际做过的检查，不用“打包通过”替代逐图审片。助手完成的初检写成候选初检，不代替用户对身份细节和审美的最终确认。
